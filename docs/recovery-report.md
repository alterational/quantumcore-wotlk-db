Оригинал ZIP не изменён. Все работы выполнены на копии. До восстановления проведена offline-проверка `myisamchk --check --read-only`: 253 комплекта прошли проверку. Есть предупреждения о незакрытых таблицах; это не было скрыто.

При открытии MySQL 5.5 для 23 таблиц потребовался `REPAIR TABLE … QUICK`: старые индексы/состояния открытия нуждались в обновлении. После этого **все 253** доступные таблицы прошли `CHECK TABLE EXTENDED` с итогом `OK`. **Все 253 SHA-256 файлов MYD совпадают с исходными**, в том числе после обновления индексов. Строки исходных данных не удалялись и не исправлялись.

13 схем извлечены через отдельные scratch-таблицы из копий `.frm`. Ни одна искусственная пустая таблица не объявлена восстановленной таблицей с нулём строк.

## Проверки

- Все 266 структуры присутствуют в JSON, в том числе у неполных таблиц.
- 253 полных `CHECK TABLE EXTENDED` и сверки `COUNT(*)` с экспортом.
- Статический экспорт: 1 498 файлов, включая каталог, схемы, чанки и SQL-архив. SHA-256 каждого чанка, число/ширина строк и типы значений проверены.
- SQL импортирован в **чистую MySQL 5.5.62**: 553 301 SQL-оператор, 266 таблиц, 553 020 строк. Повторно проверены таблицы и структура полей; потоковые хеши всех значений совпали с JSON.
- Историческая `mysql` импортируется как `legacy_mysql`, не затрагивая системные привилегии целевого сервера.
- Проверены браузерная навигация, project-Pages подкаталог, пагинация, поиск по полю, кириллица, пустые/неполные таблицы, отмена, сбои HTTP, повторная загрузка, безопасный вывод HTML-подобных значений и мобильный экран 375 px.
- Локальный замер Chromium: главная загружает ~43 КБ ресурсов плюс HTML, без данных строк. Страница `spell_dbc` (4 600 ячеек с номером строки) отобразилась примерно за 0,6 с при CPU throttling ×6. Это локальный замер, **не гарантия скорости реального телефона или GitHub Pages**.
- Обычная страница — 50 строк; чанк — максимум 500 строк / 128 КиБ для этого архива. Поиск — Web Worker, одна часть в памяти, до 200 совпадений, явное ограничение результатов.
