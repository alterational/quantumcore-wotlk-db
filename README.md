# QuantumCore WotLK — read-only архив Denwer

[Открыть сайт](https://alterational.github.io/quantumcore-wotlk-db/) · [Отчёт восстановления](docs/recovery-report.md) · [SQL-дамп](data/quantumcore-mysql55.sql.gz)

Статический поисковик для GitHub Pages. **Без сервера, регистрации и операций изменения данных.** Исходный `data.zip` сохранён без изменений.

## Что восстановлено

| Раздел | Таблиц | Доступных строк |
|---|---:|---:|
| `world` | 157 | 550 139 |
| `characters` | 77 | 1 157 |
| `realmd` — авторизация, аналог `auth` | 9 | 4 |
| `mysql` — исторические служебные таблицы | 23 | 1 720 |
| **Всего** | **266** | **553 020** |

**Архив неполный.** У 13 таблиц `world` отсутствуют `.MYD`, у четырёх из них также `.MYI`. Среди них `creature`, `creature_template`, `item_template`, `quest_template`. Структуры восстановлены из `.frm`, но строки невозможно извлечь из отсутствующих файлов. Сайт отличает такие таблицы от действительно пустых. Это **не полная рабочая база игрового сервера** — для неё нужны недостающие исходные файлы. [Полный список](docs/recovery-report.md#недостающие-файлы).

## Возможности сайта

- Все базы и таблицы, фильтр каталога по названию.
- Просмотр полей, типов, ключей, комментариев и исходного `CREATE TABLE`.
- Поиск **по всей выбранной таблице**, по всем полям или одному, точное совпадение или подстрока, без учёта регистра, включая кириллицу.
- 50 строк на странице, переход в начало/конец, хлебные крошки, браузерные «назад/вперёд» и прямые ссылки `#world/таблица`.
- Полное значение длинной ячейки открывается нажатием, в том числе с клавиатуры.
- Явные состояния пустой/неполной таблицы, ошибки загрузки, прогресс и остановка поиска.

### Почему не тормозит от размера всей базы

Нет React, внешних шрифтов, CDN, аналитики, WebAssembly и единого многомегабайтного файла БД. Главная получает только каталог. Строки загружаются небольшими JSON-частями (**не более 500 строк / примерно 128 КиБ**). На экране максимум 50 строк; кэш страницы ограничен тремя частями. Поиск работает в Web Worker, читает по одной части и останавливается на **200 совпадениях**, явно предлагая уточнить запрос. Он не скачивает другие таблицы.

Поиск без совпадений должен прочитать всю выбранную таблицу, поэтому его время зависит от сети и размера таблицы. Глобального полнотекстового поиска сразу по всем базам и произвольного SQL нет. Цифры точных типов хранятся строками JSON, чтобы браузер не округлял `BIGINT` и `DECIMAL`. `NULL`, пустые строки и двоичные значения различаются.

## GitHub Pages

Используется существующая настройка **Deploy from a branch → `main` → `/ (root)`**. `index.html`, `assets/`, `data/` лежат прямо в корне; `.nojekyll` отключает преобразование статических файлов. Все пути относительные и работают в `/quantumcore-wotlk-db/`.

Сборка сайта не требуется. После слияния изменений в `main` GitHub Pages публикует их автоматически. Workflow `Archive verification` только тестирует, не меняет способ публикации.

Локальный запуск:

```sh
python3 -m http.server 8080 --bind 0.0.0.0
# Открыть http://localhost:8080/ (не file://)
```

## SQL-дамп / MySQL / MariaDB

`data/quantumcore-mysql55.sql.gz` — компактный логический дамп с 266 структурами и 553 020 доступными строками. В комментариях помечены таблицы, у которых отсутствуют исходные строки; для них в дампе только структура.

**Импортировать только в отдельный чистый экземпляр**, предварительно сделав резервную копию. Дамп создаёт `world`, `characters`, `realmd`, **`legacy_mysql`**. Историческая `mysql` намеренно переименована, чтобы не перезаписывать системные таблицы и пользователей текущего сервера. `DROP DATABASE` / `DROP TABLE` в дампе нет; конфликт с существующими таблицами должен остановить импорт. Не используйте `--force`.

```sh
gzip -t data/quantumcore-mysql55.sql.gz
# Для современной MariaDB:
gzip -dc data/quantumcore-mysql55.sql.gz | mariadb --default-character-set=utf8mb4 -u root -p
# Для изолированного MySQL 5.5: та же команда с клиентом mysql.
```

Старые `.frm/.MYD/.MYI` **не копировать** прямо в production MariaDB. Сначала восстановление на копии в совместимом MySQL, потом логический импорт. MySQL 5.5 давно не поддерживается: он использован только как изолированный инструмент восстановления без TCP-порта. Для нового самостоятельного сервера предпочтительна поддерживаемая MariaDB. Для GitHub Pages сервер БД вообще не нужен.

Восстановленные исторические служебные таблицы — справочный материал, а не миграция привилегий современной БД. Виртуальные `information_schema` / `performance_schema` не выдаются за разделы исходного архива.

## Проверки

```sh
npm ci
npm test                           # unit-тесты + проверка всех JSON
npx playwright install --with-deps chromium
npm run test:browser                # браузер, включая project Pages подкаталог
```

Для `test:browser` каталог репозитория должен называться `quantumcore-wotlk-db` (как при обычном клонировании). Можно задать `CHROMIUM_PATH` для установленного Chromium.

CI также импортирует SQL в чистую MariaDB 10.11, проверяет все таблицы и сверяет каждое значение с JSON. Локальный MySQL 5.5 round-trip сохранён в [docs/roundtrip-checks.json](docs/roundtrip-checks.json). [Процедура повторного восстановления](docs/recovery.md).

## Публичность и read-only

Пользователь подтвердил, что аккаунты в архиве тестовые, и разрешил публикацию данных. **Read-only — не защита конфиденциальности:** все JSON, SQL и исходный ZIP публичны и могут быть скачаны. Никаких реальных паролей, email или IP из других архивов сюда добавлять нельзя без проверки. У сайта нет API записи, однако владелец репозитория по-прежнему может менять файлы через Git.
